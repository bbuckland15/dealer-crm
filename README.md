# Dealership Sales CRM

A from-scratch clone of the kind of internal tool a dealership sales team uses to
track leads, log notes, and follow up with interested customers — built as a
portfolio project.

**Stack:**
- **Backend:** Python, FastAPI, SQLAlchemy (SQL database — SQLite for local dev,
  drop-in switch to PostgreSQL for "production")
- **Frontend:** React (Vite)
- **Agentic AI:** Claude API drafts personalized follow-up messages to
  interested customers based on their notes and status. A human always
  reviews before anything is sent — nothing here auto-sends messages.

## Running it locally

You'll need Python 3.11+, Node 18+, and git. See **MAC_SETUP.md** in this repo
for a full walkthrough of installing all of this on macOS from scratch.

### 1. Backend

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # then edit .env if you want the AI outreach feature
uvicorn app.main:app --reload
```

The API runs at http://localhost:8000. Interactive docs (auto-generated by
FastAPI) are at http://localhost:8000/docs — useful for poking at endpoints
without the frontend.

### 2. Frontend

In a second terminal:

```bash
cd frontend
npm install
npm run dev
```

The app runs at http://localhost:5173 and proxies API calls to the backend.

### 3. Try it out

1. Click **+ New Lead**, add a customer (e.g. "Jane Doe", interested in a
   "2024 Tiguan").
2. Click the customer, add a note ("Test drove it, loved the interior").
3. Click **Draft follow-up message** to have Claude generate a follow-up
   based on that context (requires `ANTHROPIC_API_KEY` in `backend/.env`).

## Where this goes next

This is a deliberately minimal starting scaffold — enough to be runnable and
demonstrate the core architecture end to end. Natural next steps, roughly in
order of what teaches the most:

1. **Auth** — add a login so only your dealership's staff can access it
   (FastAPI has good guides for OAuth2 + JWT).
2. **Postgres in prod** — switch `DATABASE_URL` from SQLite to a real
   Postgres instance (Railway, Render, and Supabase all have free tiers) and
   add Alembic migrations (already in `requirements.txt`, not yet wired up).
3. **Scheduled outreach** — instead of drafting on-demand, add a background
   job (e.g. APScheduler or a cron) that finds customers who haven't been
   contacted in N days and drafts (or, once you trust it, sends) follow-ups.
4. **Real send capability** — wire the draft endpoint up to an email/SMS
   provider (SendGrid, Twilio) behind an explicit "send" button.
5. **Deployment** — deploy backend to Render/Fly.io/Railway and frontend to
   Vercel/Netlify so you have a live link for your resume/portfolio.
